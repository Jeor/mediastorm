# Cricket and golf normalization evidence

Captured 2026-09-24 with at most two concurrent ESPN requests. `cricket-series-validation.json` records exact URLs, response dates, provider league identity and event states. Raw responses are preserved here; compact `backend/services/sports/testdata/cricket-*-scoreboard.json` fixtures retain only normalization fields from those responses. The four-innings live fixture in the test is synthetic; the four-innings final 23805 fixture is captured provider data.

Discovery returns candidates, not supported leagues. Empty slugs are ignored even when a provider `id` exists. IPL retains `cricket-8048`. A series is never collapsed into a recurring trophy ID. The dropdown reports 500 entries and is not exhaustive: tested `page=2` and `year=2026` still return the same first/last entries. The documented Cricinfo competition selector returned 403; it was not bypassed. The 21 target dispositions are in `cricket-target-validation.json`: three international series families have limited sampled coverage, while eighteen recurring competition targets still lack verified mappings. No main tournament was substituted with its qualifier or warm-up competition.

`DiscoverCricketSeries` uses the service HTTP client and a 24-hour disk snapshot, preserves the last good result on errors, and does not mutate the global registry. Its caller must keep this optional discovery request outside the score path. Root integration owns the discovery route and activation of evidence-backed series.

Cricket score text, runs, wickets and overs remain separate. Overs such as 24.2 are preserved without decimal arithmetic. `isBatting` establishes innings ownership; `isCurrent` only becomes a currently batting flag during live play. Targets come from the explicit innings field or the current innings' provider score text. Scheduled events do not expose innings placeholders. Provider result summaries remain literal, including draws, rain and no-result descriptions. String/JSON winner booleans are accepted; malformed values return a decode error.

Golf audit: the existing athlete leaderboard normalizer already serves all golf league slugs, preserves raw to-par strings, rounds and holes, and leaves competitor-less schedules usable. It does not claim cut, withdrawal or disqualification detail without provider fields. TGL explicitly bypasses that normalizer so team sides survive; root integration owns expansion of its nested competitions. Optional summary failure does not participate in this scoreboard normalization.

Validation: all sports service tests passed (`go test ./services/sports -count=1`) including discovery cache/failure tests, all seven captured international series, four innings, score strings, genuine zeros, scheduled placeholders and string booleans. Device/UI verification is outside this backend module.
