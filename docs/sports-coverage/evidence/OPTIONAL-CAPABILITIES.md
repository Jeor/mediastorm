# Optional endpoint validation

`optional-capabilities.json` contains one entry per active ESPN candidate. Each entry records exact request URL, retrieval timestamp, response size/hash/status, compact or provider-shaped fixture, observed identities and the capability gate result. The batch has at most four concurrent requests, explicit timeout/size bounds and no retries. No team/standings/summary response is activated merely for HTTP 200.

- `teams`: requested limit1000, exact league slug matching, returned team count, unique named IDs and all response/league count and pagination fields. `complete` requires an explicit provider total equal to the unique named result count, no next page, fewer than the requested cap and no malformed/duplicate identities. Missing count metadata remains unverified. This avoids equating a larger limit with a complete team catalog. Compact fixtures preserve team identity fields while omitting repeated image/link arrays.
- `standings`: requested `season=2026`; the returned league UID must match the independently validated scoreboard league ID. At least one actual named team/statistics row must exist, and every nonempty table must explicitly identify2026. Default standings can silently be historical; NCAA baseball default returned2025 in the preliminary check even though its team catalog describes2026. All returned table seasons/counts remain recorded, including failures. This validates rows for the sampled season, not historical-query behavior or live refresh.
- `summary`: selected previously sampled families from the handoff and a current2026 event from the independently fetched fixture. Returned header event ID must match the request; named participant structures and at least one nonempty optional section must exist. A successful summary does not imply every section, every event state, play-by-play or roster completeness.

Only strings in each row's `capabilities` passed the gates. Failures remain isolated: they must not suppress schedules. No application source or catalog was changed by this task. Caller implementations must preserve these endpoint parameters and identity/season checks for runtime data.
